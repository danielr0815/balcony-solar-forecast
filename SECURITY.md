# Security reporting

Do not post credentials, HA tokens, session cookies or private browser profiles
in issues or pull requests. Before sharing diagnostics, inspect the complete
file, including custom entity names and exception text, for private information.

For a suspected vulnerability, use GitHub's **Security → Report a vulnerability**
for this repository when private reporting is available. If it is unavailable,
open an issue requesting a private reporting channel without exploit details
or private data. A response-time commitment has not been established.

Describe the affected integration/HA versions, impact and a minimal reproduction
using synthetic data. Ordinary forecast accuracy or usability bugs belong in
the public issue tracker with redacted evidence. Releases, dependency checks
and disclosure coordination use the normal review workflow.
